# ==============================================================================
# Developer Suite - Frozen Build Dependencies
# ==============================================================================
# Used ONLY to build the Developer Suite's Windows PyInstaller executable
# (see packaging/pyinstaller/developer_suite.spec and
# packaging/installer/setup_developer_suite.iss). This is this
# application's own trimmed dependency list, independent of
# requirements-runtime.txt (the Attendance Client's own frozen-build
# list) -- the two applications are built, versioned, and distributed
# separately, and this file contains only packages actually imported by
# developer_suite/ and the shared modules it reuses (config.py,
# database/, licensing/, utils/).
#
# Notably absent versus requirements-runtime.txt: bcrypt, pyzk,
# python-barcode, qrcode, requests. The Developer Suite never imports
# any of them -- its admin authentication is a pure HTTP client against
# the Attendance Server's own bcrypt-hashed accounts (see
# developer_suite/admin/), and it has no biometric-device or
# QR/barcode code of its own.
#
# Install with: pip install -r requirements-developer-suite-runtime.txt
# Target interpreter: Python 3.11-3.13 (match the interpreter used to run
# PyInstaller on the Windows build machine).
# ==============================================================================

# ---- PyInstaller/setuptools packaging fix (not imported by app code) --------
# Same fix requirements-runtime.txt documents in detail: modern
# setuptools vendors pkg_resources, whose bundled jaraco.context imports
# backports.tarfile under Python < 3.12, and PyInstaller always bundles
# pkg_resources's runtime hook once pkg_resources is present in the
# build venv at all -- so the frozen .exe crashes at startup with
# "ModuleNotFoundError: No module named 'backports'" unless this is
# installed too. This is a build-tool-level issue, not specific to
# either application's own code.
